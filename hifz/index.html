Routine settings

How the signature works

PIN → key. The teacher's PIN is never stored. It's run through PBKDF2 (a deliberately slow key-stretching function, 210,000 rounds) to make a 256-bit key. The app keeps only a hash of that key, so it can check the PIN is right.

Key → signature. Each sign-off hashes the day's sessions (which ayat, grades and mistakes) and computes an HMAC-SHA-256 (a keyed hash that only someone holding the PIN can produce) over them. Editing a signed session afterwards changes its hash, and the ledger check flags it.

Hash chain. Every record includes the previous record's hash, so deleting or reordering a record breaks the chain. That makes the ledger tamper-evident (changes can't be hidden).

Limit of local mode. The PIN and the ledger sit on the same phone, so this proves "someone with the PIN signed here". It doesn't give nonrepudiation (the teacher can't later deny signing). A short PIN on a device you control can also be guessed offline.

When it goes live. Swap the PIN for a per-teacher passkey. That's an ECDSA public-key signature (the teacher's device holds a private key that never leaves it), with records counter-signed on the server. Then each signature is attributable to the teacher and can't be forged by the student.
